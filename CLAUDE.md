# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Asked. — a public FAQ tool for creators. Laravel 13 + Inertia v3 + React 19 + Tailwind v4 built around **team-based multi-tenancy** with Fortify auth (including 2FA). Database is SQLite (`database/database.sqlite`).

## Common commands

- **Run everything (server + queue + logs + Vite)**: `composer run dev`
- **Frontend dev only**: `npm run dev` — must be running for Inertia pages to render in browser. Without `npm run build` or a dev server, you'll get a Vite manifest error.
- **Build assets**: `npm run build` (or `npm run build:ssr` for SSR build)
- **Full CI check** (lint + format + types + tests): `composer run ci:check`
- **PHP lint/fix**: `vendor/bin/pint --dirty --format agent` (run after editing PHP, per Boost rules)
- **JS lint/format/types**: `npm run lint`, `npm run format`, `npm run types:check`
- **Run all tests**: `php artisan test --compact`
- **Run a single test file**: `php artisan test --compact tests/Feature/Teams/CreateTeamTest.php`
- **Filter by name**: `php artisan test --compact --filter=testName`
- **Create a Pest test**: `php artisan make:test --pest SomeFeatureTest` (omit the `Feature/` prefix)
- Tests do NOT auto-use `RefreshDatabase` (see `tests/Pest.php`); apply it per-file/group as needed.

## Architecture

### Team-based URL prefixing (critical)
All authenticated app routes are nested under `{current_team}` (the team slug):
- `routes/web.php` wraps the dashboard in `Route::prefix('{current_team}')->middleware(['auth','verified', EnsureTeamMembership::class])`.
- `App\Http\Middleware\SetTeamUrlDefaults` (registered in `bootstrap/app.php`) calls `URL::defaults(['current_team' => …, 'team' => …])` so `route()` calls don't need to pass the slug explicitly.
- `App\Http\Middleware\EnsureTeamMembership` (1) 403s non-members, (2) optionally enforces a minimum role passed as middleware param, and (3) auto-switches `current_team_id` when the URL slug differs from the user's current team.
- `Team` uses `slug` as its route key (`getRouteKeyName()`).
- When adding new authenticated team-scoped routes, place them inside the `{current_team}` group; for global authenticated routes (like invitation acceptance, settings), use a plain `auth` group.

### Roles & permissions
- `App\Enums\TeamRole` (Owner/Admin/Member) and `App\Enums\TeamPermission` define a hierarchy via `level()` and a `permissions()` map.
- `App\Concerns\HasTeams` (mixed into `User`) is the source of truth: `belongsToTeam`, `ownsTeam`, `teamRole`, `hasTeamPermission`, `switchTeam`, `toUserTeam`, `toTeamPermissions`.
- `App\Policies\TeamPolicy` delegates to `hasTeamPermission`; prefer adding new permissions to the enum + policy instead of ad-hoc checks.
- Owner is auto-assigned in `App\Actions\Teams\CreateTeam`. Personal teams are created with `is_personal = true` (typically in `App\Actions\Fortify\CreateNewUser`).

### Inertia shared data
`App\Http\Middleware\HandleInertiaRequests` shares: `auth.user`, `currentTeam` (UserTeam DTO), `teams` (collection of UserTeam), `sidebarOpen`, app `name`. Frontend reads these via `usePage().props`.

### Frontend conventions
- Pages live in `resources/js/pages/`. Layout selection is centralized in `resources/js/app.tsx`:
  - `welcome` → no layout
  - `auth/*` → `AuthLayout`
  - `settings/*` and `teams/*` → nested `[AppLayout, SettingsLayout]`
  - everything else → `AppLayout`
- Path alias `@/*` → `resources/js/*` (see `tsconfig.json`).
- Use **Wayfinder** for typed routes/actions: import from `@/actions/*` (controllers) or `@/routes/*` (named routes). Generated by `@laravel/vite-plugin-wayfinder`; never hardcode URLs.
- UI primitives are shadcn-style under `resources/js/components/ui`. Reuse before adding new components.
- React Compiler is enabled (`babel-plugin-react-compiler` in `vite.config.ts`); avoid manual `useMemo`/`useCallback` unless profiling shows a need.

### Fortify auth
- `App\Providers\FortifyServiceProvider` wires Inertia views for every auth flow (login, register, password reset, email verify, 2FA challenge, password confirm) and registers `login`/`two-factor` rate limiters (5/min).
- Custom response classes in `App\Http\Responses` (`LoginResponse`, `RegisterResponse`, `TwoFactorLoginResponse`) handle post-auth redirects — modify these rather than overriding Fortify's controllers.
- User creation is handled by `App\Actions\Fortify\CreateNewUser`; password reset by `App\Actions\Fortify\ResetUserPassword`.

### Search Syntax

1. Use words for auto-stemmed AND logic: `rate limit` matches both "rate" AND "limit".
2. Use `"quoted phrases"` for exact position matching: `"infinite scroll"` requires adjacent words in order.
3. Combine words and phrases for mixed queries: `middleware "rate limit"`.
4. Use multiple queries for OR logic: `queries=["authentication", "middleware"]`.

=== inertia-laravel/core rules ===

# Inertia

- Inertia creates fully client-side rendered SPAs without modern SPA complexity, leveraging existing server-side patterns.
- Components live in `resources/js/pages` (unless specified in `vite.config.js`). Use `Inertia::render()` for server-side routing instead of Blade views.
- ALWAYS use `search-docs` tool for version-specific Inertia documentation and updated code examples.
- IMPORTANT: Activate `inertia-react-development` when working with Inertia client-side patterns.

# Inertia v3

- Use all Inertia features from v1, v2, and v3. Check the documentation before making changes to ensure the correct approach.
- New v3 features: standalone HTTP requests (`useHttp` hook), optimistic updates with automatic rollback, layout props (`useLayoutProps` hook), instant visits, simplified SSR via `@inertiajs/vite` plugin, custom exception handling for error pages.
- Carried over from v2: deferred props, infinite scroll, merging props, polling, prefetching, once props, flash data.
- When using deferred props, add an empty state with a pulsing or animated skeleton.
- Axios has been removed. Use the built-in XHR client with interceptors, or install Axios separately if needed.
- `Inertia::lazy()` / `LazyProp` has been removed. Use `Inertia::optional()` instead.
- Prop types (`Inertia::optional()`, `Inertia::defer()`, `Inertia::merge()`) work inside nested arrays with dot-notation paths.
- SSR works automatically in Vite dev mode with `@inertiajs/vite` - no separate Node.js server needed during development.
- Event renames: `invalid` is now `httpException`, `exception` is now `networkError`.
- `router.cancel()` replaced by `router.cancelAll()`.
- The `future` configuration namespace has been removed - all v2 future options are now always enabled.
